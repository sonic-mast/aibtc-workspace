As of 2026-08-03 (discovered mid-run, ~16:07 UTC), aibtc.news is no longer a newsroom server with a database. `news_check_status`, `news_list_signals`, and (by extension) `news_file_signal` / `news_file_correction` / the whole beat model return `410 Gone` with `"deprecated": true`. The 410 body itself documents the replacement in full.

**Why:** aibtc.news is now a read-only window onto two Stacks **testnet** contracts — `STGX5YP51NKM69ZMP6DVB6GAJAANCG5WB3718KD9.news-gov-v5-testnet` (governance) and `...news-treasury-v5` (treasury). There is no more filing/editing/reviewing on a server: an agent inscribes its own piece to Bitcoin, contributes sBTC to the pool for voting weight, opens a proposal naming the inscription link, other contributors vote/veto, and `conclude` pays the proposer from the treasury if it passes. `GET https://aibtc.news/api/state` is the one read that replaces `news_check_status`/`news_list_signals`/the old front page — it returns every proposal, live vote tallies, pool balance, total weight, and the sponsor board.

New mechanics observed live: `votingDelay=4` blocks before voting opens, `voteWindow=24`, `vetoWindow=6`, `concludeWindow=12`, `votingThreshold=66%`, `votingQuorum=15`, `vetoQuorum=15`, `minParticipants=2`, `minWeight=10000`. Proposing locks a non-refundable weight bond (`bond` field, e.g. 10,000,000 in observed proposals) that only releases on an outcome (pass/fail/expire), not on withdrawal. A passed proposal pays the proposer a `draw` snapshotted at propose time. Sponsoring the pool (`sponsor-in` on the treasury contract) buys no voting weight — it's the old classifieds-slot equivalent. Full contract interface is documented at `https://aibtc.news/skill.md`.

**This breaks essentially all of the combined prompt's news correspondent machinery**: Phase 3 (quota/status check), Phase 4 (beat selection, sourcing gates, signal composition/filing — the entire beat/score/editor model is gone), Phase 4f (corrections — `news_file_correction` no longer exists as a concept), and Phase 6a (signal performance review via `publisherFeedback`/rejection reasons — there is no more per-signal editorial feedback, only pass/fail votes). It likely also obsoletes most of the beat-scoring/rejection-pattern memories accumulated since April 2026 (`news-filing.md`, `news-audit-2026-04-27.md`, `eic-rubric-v3.md`, `project_eic_pause.md`, `identity-service-extended-outage.md`, `sec-bitcoin-structured-notes.md`) — those all describe a server-side editorial process that no longer runs. Don't delete them yet without confirming the old system is fully gone (not a partial rollout / A-B test) and without a deliberate consolidation pass; this entry just flags the break.

**2026-08-04 update — native MCP tools shipped.** `aibtcdev/aibtc-mcp-server` PR #642 (merged 2026-08-03T16:41Z) added `legion_*` tools so this surface no longer needs hand-rolled `call_contract`/curl. Read tools confirmed working live this run: `legion_status` (pool/params/current draw), `legion_list_stories` (proposals by phase), `legion_get_story`, `legion_my_position`. Write tools also shipped (`legion_contribute`, `legion_sponsor`, `legion_propose_story`, `legion_vote`, `legion_veto`, `legion_conclude`, `legion_faucet`, plus inscription tools `legion_inscribe_story`/`legion_inscribe_reveal`) but the operator-decision gate below still applies to those — tool availability isn't the same as authorization to spend. Oddity: the tools work even though this machine's installed `@aibtc/mcp-server` reports `1.64.0` in both `npm ls -g` and the package.json on disk (`/opt/homebrew/lib/node_modules/@aibtc/mcp-server`) — latest on npm is `1.66.0`. Don't trust the version-lag check alone to gate on whether a feature exists; probe the actual tool. `legion_status` is pinned to testnet regardless of the server's `NETWORK=mainnet` env (network is derived from the `ST…`/`STGX…` contract address prefix), confirmed live: pool balance ~30,039,847 sats testnet-sBTC, `totalProposals=5`, 0 currently in a live phase (pending/voting/veto/concludable).

**2026-08-04 re-check (later run, ~10:xx UTC):** `news_check_status` still returns the identical 410 body — second-day confirmation this is a real migration, not a one-off blip or A/B rollout. `legion_status`/`legion_list_stories` still show `totalProposals=5`, 0 live — no proposal activity since the prior check.

**Inscribe base64-transit-truncation risk (aibtc-mcp-server #644, filed by Secret Mars 2026-08-04, commented on same day).** The underlying `inscribe`/`inscribe_reveal` primitive that `legion_inscribe_story`/`legion_inscribe_reveal` will use can silently drop bytes from the base64 `content` param in MCP transit. Secret Mars's commit call reported `contentSize: 2752` for a payload that decoded locally to 2765 bytes (verified sha256) — 13 bytes short — and the reveal then failed on all fee-rate retries with `mempool-script-verify-flag-failed (Witness program hash mismatch)`, permanently locking the reveal-address sats (no way to reconstruct the dropped bytes). Our own 140-byte inscription the day before (2026-08-03, the "ship one inscription" bounty round-1/round-2 — see [[bounty-audit-fix-pr-infeasible]]) went through clean with sha256 matching, so this looks size/content-dependent — small payloads survive, larger ones are at risk. No fix has shipped as of this check.

**How to apply:**
- Phase 3/4/4f/6a of the combined prompt stay skipped (`newsStatus: "api-migrated"` or similar) — none of that machinery is back.
- Prefer `legion_status` / `legion_list_stories` / `legion_get_story` / `legion_my_position` over raw curl for any future read on this system — they're live and already resolve network/params/preconditions.
- Do **not** autonomously call any legion write tool (`legion_contribute`, `legion_sponsor`, `legion_propose_story`, `legion_vote`, `legion_veto`, `legion_conclude`, `legion_faucet`, `legion_inscribe_*`). Tool availability changed 2026-08-04; the underlying decision has not — this is a new financial mechanism (locked bonds, real inscription fees) on a **testnet** contract but still a material strategy change, needs an explicit operator decision before the combined prompt is rewritten for it, same principle as [[bounty-audit-fix-pr-infeasible]] (real-payment actions need live confirmation, not autonomous drafting).
- `reference/aibtc.news/llms.txt` / `llms-full.txt` are now stale and describe the dead API — don't trust them for this surface until refreshed from `https://aibtc.news/skill.md`.
- If `news_check_status`/`news_list_signals` start working again, treat it as a possible A/B rollout or rollback, not a code bug on our end — re-probe before assuming it's fixed for good.
- **Before any future `inscribe`/`inscribe_reveal` or `legion_inscribe_*` call on a nontrivial payload** (bigger than the ~140-byte payloads used so far): compare the `contentSize` (and sha256, once aibtc-mcp-server #644's fix #1 ships) the commit call returns against the local decoded length/hash. Mismatch = abort, do not call reveal — the funds are unrecoverable once a mismatched reveal is attempted.
